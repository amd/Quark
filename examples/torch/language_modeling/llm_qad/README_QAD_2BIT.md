# 2-bit QAD (Quantization-Aware Distillation) — full-weight

End-to-end recipe to produce a **pure 2-bit** weight model (4 levels per group,
no LoRA, no rotation at inference) by distilling from a BF16 teacher. This is
the QAD v6 pipeline used for **Phi-4 (14B)** and **QwQ-32B**.

Pipeline (all in `train_qad_2bit_fullweight.py`):

```text
2-bit PTQ student  →  Block-AP warmup  →  E2E QAD KD (JSD)  →  eval  →  packed export
   (TwoBitScalar)      (--block_ap_warmup)   (resume warmup)              (export_qad_2bit_packed.py)
                                            ↑ teacher reasoning traces (generate_reasoning_traces.py)
```

Run everything from the repo root and export `QUARK_ROOT` (used to locate the
reasoning-trace JSONL files):

```bash
export QUARK_ROOT=/workspaces/Quark
cd "$QUARK_ROOT"
```

## Prerequisites

Beyond an installed Quark (from this branch) + PyTorch/transformers, the example
scripts need a few extra packages:

```bash
pip install peft "lm-eval>=0.4" datasets   # + trl only for --use_qad_trainer (QADSFTTrainer)
```

- `peft` — LoRA adapters and loading the Quark-native export with an adapter
- `lm-eval` (lm-evaluation-harness) — the downstream tasks in Step 3
- `datasets` — the training/eval data mix (usually pulled in by `transformers`)

## Step 0 — Generate teacher reasoning traces

The QAD v6 data mix includes math/reasoning chain-of-thought **generated by the
BF16 teacher**. `generate_reasoning_traces.py` writes a JSONL (chat `messages`
format) that the task mix loads via a per-model task name. **The output filename
is fixed per model** (the dataset loader looks it up under `$QUARK_ROOT`):

| Model | task name | expected file (`$QUARK_ROOT/...`) |
|-------|-----------|-----------------------------------|
| Phi-4 | `phi4_bf16_traces` | `phi4_bf16_reasoning_traces.jsonl` |
| QwQ-32B | `reasoning_jsonl` | `qwq32b_reasoning_generated.jsonl` |

Sources: `openmath` (`nvidia/OpenMathInstruct-2`) and `orca_math`
(`microsoft/orca-math-word-problems-200k`). Shard across GPUs and merge with `cat`.

**Phi-4** (4-way shard, ~20k traces):

```bash
for g in 0 1; do CUDA_VISIBLE_DEVICES=$g python generate_reasoning_traces.py \
    --gpu_id $g --num_shards 4 --source openmath \
    --model_dir /amd_models/microsoft/phi-4 \
    --max_per_source 10000 --output /tmp/phi4_traces_$g.jsonl & done
for g in 2 3; do CUDA_VISIBLE_DEVICES=$g python generate_reasoning_traces.py \
    --gpu_id $g --num_shards 4 --source orca_math \
    --model_dir /amd_models/microsoft/phi-4 \
    --max_per_source 10000 --output /tmp/phi4_traces_$g.jsonl & done
wait
cat /tmp/phi4_traces_*.jsonl > "$QUARK_ROOT/phi4_bf16_reasoning_traces.jsonl"
```

**QwQ-32B** (same, just swap model + output name):

```bash
for g in 0 1; do CUDA_VISIBLE_DEVICES=$g python generate_reasoning_traces.py \
    --gpu_id $g --num_shards 4 --source openmath \
    --model_dir /amd_models/Qwen/QwQ-32B \
    --max_per_source 10000 --output /tmp/qwq_traces_$g.jsonl & done
for g in 2 3; do CUDA_VISIBLE_DEVICES=$g python generate_reasoning_traces.py \
    --gpu_id $g --num_shards 4 --source orca_math \
    --model_dir /amd_models/Qwen/QwQ-32B \
    --max_per_source 10000 --output /tmp/qwq_traces_$g.jsonl & done
wait
cat /tmp/qwq_traces_*.jsonl > "$QUARK_ROOT/qwq32b_reasoning_generated.jsonl"
```

> If you omit the trace file, drop the corresponding task name (`phi4_bf16_traces`
> / `reasoning_jsonl`) from `--task_include`; the rest of the mix still runs.

## Step 2 — Block-AP warmup + E2E QAD KD

`train_qad_2bit_fullweight.py` runs both phases. Pass `--block_ap_warmup` the
first time (it saves `<output_dir>/block_ap_checkpoint`, then continues into E2E
KD). To re-run E2E from an existing warmup, pass `--block_ap_resume <dir>` instead.

Both phases distill from the BF16 teacher: Block-AP via per-block MSE, E2E via JSD
logit KD (`alpha*KD + (1-alpha)*CE`). Final weights take exactly 4 levels/group.

> **Note.** The reported v6 results use standard (off-policy) KD. The
> `--on_policy_kd` flag is an optional/experimental add-on that generates from the
> student every N steps (~5x slower per step under `device_map` model-parallelism)
> and is **not** part of the v6 recipe — leave it off to reproduce the numbers
> below. The original v6 also **resumed** Block-AP from the v5 checkpoint
> (`--block_ap_resume /tmp/phi4_qad_v5/block_ap_checkpoint`); a fresh student uses
> `--block_ap_warmup` as shown.

### Phi-4 (14B) — 4 GPUs

```bash
FAIR="sciq,commonsenseqa,piqa,siqa,race,swag,qasc,copa,copa_sg,rte,cb,multirc,record,wic,triviaqa,slimpajama"
MATH="metamathqa,mathinstruct,orcamath,openthoughts,aqua_rat,svamp,phi4_bf16_traces"

CUDA_VISIBLE_DEVICES=0,1,2,3 python train_qad_2bit_fullweight.py \
  --model_dir /tmp/phi4_lloyd_max_g64 \
  --teacher_model_dir /amd_models/microsoft/phi-4 \
  --output_dir /tmp/phi4_qad_v6 \
  --multi_gpu --bf16 --gradient_checkpointing --attn_implementation sdpa \
  --group_size 64 \
  --dataset taskmix --task_include "$FAIR,$MATH" --use_slimpajama \
  --max_per_task 15000 --max_raw_pile 50000 --max_train_samples 200000 --seq_len 1024 \
  --per_device_train_batch_size 2 --gradient_accumulation_steps 4 \
  --block_ap_warmup --block_ap_epochs 2 --block_ap_samples 4096 \
  --max_steps 60000 --warmup_steps 2000 --lr 5e-6 \
  --kd_mode output --kd_loss_type jsd --kd_temperature 1.2 --kd_alpha 0.85 \
  --learned_scales --scale_lr_mult 10.0 \
  --log_loss_breakdown --logging_steps 25 --save_steps 2500 --eval_every 2500
```

## Step 4 — Packed 2-bit export (deployable)

There are two export formats; both encode the exact same 4-level weights
(`levels{-1,-1/3,1/3,1}[idx] * per-group-max-abs`) and give **identical PPL /
downstream accuracy**.

### Step 4a — Quark-native uint2 export (recommended)

Produces a standard Quark checkpoint loadable by `import_model_from_safetensors`.

```bash
python export_qad_quark_native_uint2.py \
  --model_dir /tmp/phi4_qad_v6 \
  --output_dir /amd_models/phi4_qad_v6_quark_uint2_native \
  --group_size 64
```

Output (Quark-native format):

- single `model.safetensors` with `{layer}.weight` (uint8, **4×uint2/byte**, `[in, out/4]`),
  `{layer}.weight_scale` (fp16, `[in/group, out]` = `2/3·max_abs`),
  `{layer}.weight_zero_point` (fp16, `1.5` — float zero-point)
- `config.json` with embedded `quantization_config` (`quant_method:"quark"`,
  `dtype:"uint2"`, `qscheme:"per_group"`, `zero_point_type:"float32"`)

Dequant is the Quark linear form `w = (idx − 1.5) · weight_scale`, which equals the
QAD codebook exactly. Load + evaluate it natively (no `trust_remote_code`):

```python
from transformers import AutoConfig, AutoModelForCausalLM, AutoTokenizer
from quark.torch import import_model_from_safetensors
d = "/amd_models/phi4_qad_v6_quark_uint2_native"
tok = AutoTokenizer.from_pretrained(d)
base = AutoModelForCausalLM.from_config(AutoConfig.from_pretrained(d))
model = import_model_from_safetensors(base, model_dir=d, multi_device=False).eval().cuda()
```

> Requires the `uint2` dtype + float zero-point support added in this PR
> (transparently present once Quark is installed from this branch).

### Step 4b — Standalone packed export (dependency-free fallback)

```bash
python export_qad_2bit_packed.py \
  --model_dir /tmp/phi4_qad_v6 \
  --output_dir /tmp/phi4_qad_v6_export \
  --model_name microsoft/phi-4
# add --skip_hf_model to skip the bf16 hf_model/ copy
```

Produces `qweights_packed.safetensors` (int2, 4/byte), `scales.safetensors`
(per-group fp16, `[out, in/group]`), `quantization_config.json`, and (optionally)
`hf_model/`. Codec: `pack_qad_2bit` / `unpack_qad_2bit` in that script. This is a
self-contained bundle (matches the AMD reference QAD export) that does **not**
depend on the Quark uint2 dtype — use it when loading outside a patched Quark.

## Results — 2-bit QAD v6 vs BF16

Pure 2-bit weight (4 levels/group, no rotation, no LoRA at inference) vs the BF16 teacher.

**WikiText-2 perplexity** (`wikitext-2-raw-v1` test split, seq_len = 2048, non-overlapping):

| Model | BF16 | QAD 2-bit | Δ |
|-------|-----:|----------:|--:|
| Phi-4 (14B) | 6.46 | 12.89 | +6.43 |
| QwQ-32B     | 6.34 | 10.12 | +3.78 |

**Zero-shot downstream accuracy** (lm-evaluation-harness, `acc`, 0-shot):

| Task | Phi-4 BF16 | Phi-4 QAD | QwQ-32B BF16 | QwQ-32B QAD |
|------|-----------:|----------:|-------------:|------------:|
| arc_challenge | 55.89 | 46.59 | 53.92 | 48.04 |
| boolq         | 86.09 | 77.43 | 86.51 | 84.62 |
| hellaswag     | 63.11 | 50.07 | 65.13 | 53.81 |
| openbookqa    | 33.80 | 29.20 | 35.00 | 28.60 |
| winogrande    | 76.64 | 64.40 | 69.85 | 69.77 |
| **5-task avg** | **63.11** | **53.54** | **62.08** | **56.97** |
| **% of BF16** | — | **84.8%** | — | **91.8%** |

**Export equivalence:** the Quark-native uint2 export (Step 4a) is lossless — Phi-4 WikiText-2
PPL is **12.8901** (uint2-native) vs **12.8915** (packed / fake-quant), Δ = 0.0014.
